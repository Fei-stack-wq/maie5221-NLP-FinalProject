# 使用个人角色库

比如你想要一位长期维护本机项目的助手。第一次告诉它“修改数据库前先备份”，以后维护其他项目时也希望它记得。至于 A 项目的启动方法和验收步骤，你可以只让它在 A 项目使用。在 Studio 侧栏打开 **角色库** 就能管理这些内容。手机上先点左上角的导航按钮。

## 创建角色并开始私聊

1. 点 **创建角色**，填写 **角色名称** 和 **角色职责**。例如名称写“电脑维护助手”，职责写“排查本机项目的运行故障，修改数据前确认备份位置，结束时给出复测结果”。
2. 点 **保存角色**。Studio 会分配固定 ID。如果要在群聊分工中用容易辨认的 ID，可以在创建时展开 **自定义角色 ID（选填）**，例如填 `local-maintainer`。之后可在 **编辑角色** 修改显示名和职责，ID 始终指向这位助手。
3. 在角色详情点 **新建私聊**。私聊角色已选好，可以在 **本地工作区（选填）** 选择项目文件夹。输入第一条消息并发送。真实私聊使用本机配置的 DeepSeek。
4. 回到角色页，用 **继续最近私聊** 接着上一段讨论。也可以从 **近期项目对话** 选择其中一个私聊或群聊。再次点 **新建私聊** 会另开一段独立对话，仍然由同一个角色接收。刚结束一轮时，在聊天页底部的 **继续对话** 输入下一步要求。上一轮正在执行时可以在该页查看状态。

想邀请角色参与群聊，进入 **对话 → 新建群聊**，勾选角色并指定负责人或本轮回复角色。同一个角色可以在一个项目里负责，在另一个项目里接受委派。每位成员使用自己有权读取的角色资料。

## 培养记忆与技能

| 你希望助手掌握什么 | 如何保存 | 例子 |
| --- | --- | --- |
| 长期偏好、约束或事实 | 在角色详情选 **记忆 → 添加记忆**，写入内容并保存 | “生成维护报告时使用中文，保留原始错误信息。” |
| 可复用的工作步骤 | 选 **技能 → 添加技能**，写下适用条件、操作步骤和验证方法 | “升级预订服务时，先备份数据库，重启后核对原预约及取消状态，再测试一次新增预约。” |
| 在私聊中明确要求记住一件事 | 向已绑定的角色单独发送以 **请记住：** 开头的一条消息 | `请记住：每次修改 SQLite 数据库前先创建备份。` |

用户通过角色页保存的条目立即启用。上面的私聊指令由宿主保存为**角色通用记忆**，也可以回到 **角色库 → 对应角色 → 记忆 → 当前** 核对。项目专属信息可在角色页填写，并选择 **仅指定项目**。

在会话中还可以让助手“把刚才验证过的重启流程整理成技能，提交给我确认”。当助手调用提议工具后，打开 **角色库 → 对应角色 → 技能 → 待确认** 查看内容及 **来源对话**。选择 **确认启用**、**编辑 → 保存并启用** 或 **拒绝**。记忆建议同样在 **记忆 → 待确认** 处理。在等待审批期间，已有条目继续使用上一次启用的内容。**当前** 展示角色实际可用的版本。

## 选对适用范围

- **角色通用 · 跨项目使用**。这份内容属于当前角色。它在新私聊或已绑定此角色的群聊里也可以使用，例如“所有 SQL 修改先备份”。
- **仅指定项目**。先以该角色参与一次目标项目的会话，再在添加条目时选择该项目。指定本地文件夹后，同一角色在不同房间选择同一个目录，可以共用该目录的项目记忆。不同目录各自保存项目知识。
- **用 Studio 管理项目文件**。没有指定本地目录时，Studio 为当前项目分配身份。正常续聊沿用这个项目。在聊天的 **本轮选项与预算** 中选择 **新任务，使用空工作区** 会开始独立的项目范围。角色通用记忆仍然可用。

例如，项目 A 的重启步骤设为 **仅指定项目**，通用的备份偏好设为 **角色通用**。打开项目 B 的独立私聊后，可以让助手复述自己的备份偏好。回到 A 的项目对话，再让它查找 A 的重启步骤。运行时会按当前要求带入部分相关条目，角色也可以用自己的检索工具读取已启用的详细内容。

## 编辑、归档与版本记录

在条目下点 **编辑 → 保存修改** 会产生一个立即生效的新版本。版本号形如 `v2`。如果另一窗口先更新了条目，页面会提示冲突，此时保留手头的改动，关闭编辑窗口并重新打开最新版本。

点 **归档** 可以停止使用该条目。在 **已处理** 中找到已归档的内容，点 **恢复使用** 可以重新启用。被拒绝的建议也可以在 **已处理** 中查看。候选改动和仍在使用的正文会保留各自的版本号，便于核对角色实际读到了什么。

需要核查完整修订记录时，本地接口 `GET /api/profiles/{role}/knowledge/{entry_id}/history` 返回各版本的正文、状态和来源。接口 `POST /api/profiles/{role}/knowledge/{entry_id}/restore` 可以恢复一个曾经启用的版本，请求携带目标 `revision`、最新 `expected_revision` 和 Studio 的写入令牌。恢复会生成新修订，之前的记录可以继续查阅。

## 关联已有会话

旧版 Studio 创建的自定义角色对话可能只保存了当时的角色资料。在角色详情的 **可关联的旧会话** 中核对会话标题，然后点 **关联已有会话**。平台会核对原来的角色 ID、名称和职责。仅名字相同、职责不同的旧成员会继续保有各自的身份。

关联成功后，该会话会出现在 **近期项目对话** 中。点进去，在原会话底部继续发送消息。从下一轮起，这位旧成员会使用持久角色当前的职责、记忆和技能。历史轮次仍能按原来的内容查看。如果关联时该会话正在执行，等它结束并刷新角色页，再关联最新一轮。

## 真实模型验证

2026-11-18 在隔离的临时 Studio 使用官方 `deepseek-flash`，关闭 thinking。先在维护员私聊要求记住一个随机工单签收码，关闭服务，用同一数据目录重启。在全新私聊询问相同问题时，维护员逐字复述了签收码。另一名角色回答“不知道”。三轮都从正常会话入口执行，验证程序单独比较了答案。这项检查验证跨会话召回与角色隔离，技能能否改善业务交付仍要由业务验收衡量。
