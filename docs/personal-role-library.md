# 使用个人角色库

比如你想要一位长期维护本机项目的助手。第一次告诉它“修改数据库前先备份”，以后维护其他项目时也希望它记得。至于 A 项目的启动方法和验收步骤，你可以只让它在 A 项目使用。在 Studio 侧栏打开 **角色库** 就能管理这些内容。手机上先点左上角的导航按钮。

## 找到角色和它接过的任务

角色库支持按名称、ID 和职责搜索。**个人角色** 包含你或统一助手保存的长期助手，可以开始新私聊，管理其记忆与技能。**历史会话成员** 来自已有对话保存的角色资料，可以返回原来的群聊或私聊。**内置角色** 包括研究员、写作者、审阅者和通用助手，首次使用前也会出现在目录里。

点开任意角色，默认显示 **分配的任务**。用 **私聊** 或 **群聊** 筛选，点击任务可定位并展开对应运行中的那条任务记录。举例来说，软件开发者的角色页能看到技术负责人交给它的预订系统实现任务。只入群、这轮没被分工的成员，在 **参与的对话** 仍能找到该群。**其他运行** 收录有具名执行者、没有对话的早期任务。页面打开期间，新的任务及执行状态会随服务轮询更新。

历史成员的固定 ID、名称和职责都相同，会在同一条公开角色记录中呈现；同名且职责不同的成员各有自己的入口。选 **保存为个人角色** 可以沿用公开的名称与职责。原 ID 已被占用时，表单会为新角色分配独立 ID。需要让新助手参加一个符合条件的旧会话时，在其 **参与的对话** 中显式关联。

## 创建角色并开始私聊

1. 点 **创建角色**，填写 **角色名称** 和 **角色职责**。例如名称写“电脑维护助手”，职责写“排查本机项目的运行故障，修改数据前确认备份位置，结束时给出复测结果”。
2. 点 **保存角色**。Studio 会分配固定 ID。如果要在群聊分工中用容易辨认的 ID，可以在创建时展开 **自定义角色 ID（选填）**，例如填 `local-maintainer`。之后可在 **编辑角色** 修改显示名和职责，ID 始终指向这位助手。
3. 在角色详情点 **新建私聊**。私聊角色已选好，可以在 **本地工作区（选填）** 选择项目文件夹。输入第一条消息并发送。真实私聊使用本机配置的 DeepSeek。
4. 回到角色页，用 **继续最近私聊** 接着上一段讨论。也可以从 **参与的对话** 选择其中一个私聊或群聊。再次点 **新建私聊** 会另开一段独立对话，仍然由同一个角色接收。刚结束一轮时，在聊天页底部的 **继续对话** 输入下一步要求。上一轮正在执行时可以在该页查看状态。

想邀请角色参与群聊，进入 **最近对话 → 新建群聊**，勾选角色并指定负责人或本轮回复角色。同一个角色可以在一个项目里负责，在另一个项目里接受委派。每位成员只收到本群的对话和派工记录。统一助手创建角色时生成的详细职责可能包含当次任务的验收要求，因此这段初稿属于创建当轮为该角色建立的第一个群。在其他群里可以复用角色身份，由本群指定分工。希望某份职责在所有群中生效，可在角色详情编辑，勾选 **将这段职责从来源会话共享到所有群和私聊** 后保存。用户在角色页直接创建的职责默认按角色复用。

## 培养记忆与技能

| 你希望助手掌握什么 | 如何保存 | 例子 |
| --- | --- | --- |
| 长期偏好、约束或事实 | 在 **记忆与技能** 中选 **记忆 → 添加记忆**，写入内容并保存 | “生成维护报告时使用中文，保留原始错误信息。” |
| 可复用的工作步骤 | 在 **记忆与技能** 中选 **技能 → 添加技能**，写下适用条件、操作步骤和验证方法 | “升级预订服务时，先备份数据库，重启后核对原预约及取消状态，再测试一次新增预约。” |
| 本次私聊需要长期保留的事实 | 向已绑定的角色单独发送以 **请记住：** 开头的一条消息 | `请记住：这次换机的工单号是 A-184。` |

用户通过角色页保存的条目立即启用。私聊里的 `请记住：` 和 `/remember` 把内容保存在该私聊。继续 A 时助手可以复述工单号。同一助手在私聊 B 使用自己的聊天记录、附件和会话记忆，即使 A 和 B 选择了同一个磁盘目录也是如此。双方主动选用同一工作区时，目录里的项目文件仍按工作区设置读取。

在会话中还可以让助手“把刚才验证过的重启流程整理成技能，提交给我确认”。当助手调用提议工具后，打开 **角色库 → 对应角色 → 记忆与技能 → 技能 → 待确认** 查看内容及 **来源对话**。选择 **确认启用**、**编辑 → 保存并启用** 或 **拒绝**。记忆建议同样在 **记忆 → 待确认** 处理。在等待审批期间，已有条目继续使用上一次启用的内容。**当前** 展示角色实际可用的版本。

## 选对适用范围

- **角色通用 · 跨项目使用**。这份内容属于当前角色。它在新私聊或已绑定此角色的群聊里也可以使用，例如“所有 SQL 修改先备份”。
- **仅此私聊**。选择 A，把 A 的临时约定留在该私聊。角色在私聊中提议记忆和技能时默认使用这个范围。想让 B 也掌握某个方法，在条目上点 **提炼为通用技能**，参考原记录，在新表单里写下适用条件、操作步骤和验证方法，再保存。也可以确认启用角色提交的通用技能建议。原私聊的消息、附件和工单号保留在 A。
- **仅指定项目**。先以该角色参与一次目标项目的会话，再在添加条目时选择该项目。用户在角色页为文件夹添加的项目资料，可供已明确绑定同一目录的房间共用。来自某轮执行的项目记忆和技能经批准后，只在来源会话的同一个项目生效。提示中的摘要、检索结果和凭条目 ID 读取正文都使用这个范围。
- **用 Studio 管理项目文件**。没有指定本地目录时，Studio 为当前项目分配身份。正常续聊沿用这个项目。在聊天的 **本轮选项与预算** 中选择 **新任务，使用空工作区** 会开始独立的项目范围。角色通用记忆仍然可用。

例如，项目 A 的重启步骤设为 **仅指定项目**，通用的备份偏好设为 **角色通用**。打开项目 B 的独立私聊后，可以让助手复述自己的备份偏好。回到 A 的项目对话，再让它查找 A 的重启步骤。运行时会按当前要求带入部分相关条目，角色也可以用自己的检索工具读取已启用的详细内容。

## 编辑、归档与版本记录

在条目下点 **编辑 → 保存修改** 会产生一个立即生效的新版本。版本号形如 `v2`。如果另一窗口先更新了条目，页面会提示冲突，此时保留手头的改动，关闭编辑窗口并重新打开最新版本。

点 **归档** 可以停止使用该条目。在 **已处理** 中找到已归档的内容，点 **恢复使用** 可以重新启用。被拒绝的建议也可以在 **已处理** 中查看。候选改动和仍在使用的正文会保留各自的版本号，便于核对角色实际读到了什么。

需要核查完整修订记录时，本地接口 `GET /api/profiles/{role}/knowledge/{entry_id}/history` 返回各版本的正文、状态和来源。接口 `POST /api/profiles/{role}/knowledge/{entry_id}/restore` 可以恢复一个曾经启用的版本，请求携带目标 `revision`、最新 `expected_revision` 和 Studio 的写入令牌。恢复会生成新修订，之前的记录可以继续查阅。

## 关联已有会话

旧版 Studio 创建的自定义角色对话可能只保存了当时的角色资料。在个人角色的 **参与的对话 → 可关联的旧会话** 中核对会话标题，然后点 **关联已有会话**。平台会核对原来的角色 ID、名称和职责。仅名字相同、职责不同的旧成员会继续保有各自的身份。

关联成功后，该会话会出现在 **参与的对话** 中。点进去，在原会话底部继续发送消息。从下一轮起，这位旧成员会使用持久角色当前的职责、记忆和技能。历史轮次仍能按原来的内容查看。如果关联时该会话正在执行，等它结束并刷新角色页，再关联最新一轮。

2026-11-18 使用官方 `deepseek-flash` 测试时，旧版会把私聊里明确要求记住的工单号带到该角色的新私聊。当前版本会按原始运行标识把这类历史条目归回来源私聊，保留原条目和版本。服务回归覆盖同一角色、同一磁盘目录下的两个私聊，分别验证原聊天续聊、外部条目 ID 与附件 ID 的读取、重启后的迁移，以及已启用的通用技能召回。[服务回归](../tests/test_studio_role_turns.py) · [角色库接口回归](../tests/test_studio_role_http.py)

## 新群的文件从哪里来

统一助手在已有对话中建立新群时，默认给新群分配独立工作区。给某个群使用源目录有两种方式：用户在创建群的这条消息中选择本地文件夹，或在 Studio 手动建群时指定目录。派工时也可以按文件名转交材料；新群可以读取这份副本。群 A 的回答、附件和执行记录按群 ID 查询，群 B 即使邀请同一位成员，也会从自己的会话继续。

文件夹是用户选择共享的材料范围，群 ID 是会话记录的范围。这个设计参考了 AutoGen 的群消息主题，以及 LangGraph 对线程状态和跨线程存储的区分。[AutoGen 群聊](https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html) · [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)
