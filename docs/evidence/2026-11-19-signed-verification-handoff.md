# 独立复核签署未决后如何交接

软件第一题运行 `studio-20261119-205052-8cb1b5bfa99c` 使用版本 `96d0eea`。独立裁决成员 `release` 的任务 `task-4731238a4bc94fba94291f2bc592a7f4` 在第 16 步签署了三项通过、一项取证未决。最后一项引用了本次失败的浏览器回执和两条通过回执。第 17 步宿主仍要求重放先前的浏览器操作，只提供 `rerun_browser_check`。交接提示同时列出了另一位成员遗留的检查脚本。模型选用提示中的 `run_shell`，宿主因当前工具列表已关闭它而拒绝调用。第 18 步成员如实以 `[BLOCKED]` 交接，宿主把整个裁决标成终止。独立验收在已公布应用上通过了 21 项检查，原群仍以失败结案。

## 评审与运行状态

每次 `submit_review` 仍记录签署者、冻结版本、逐项结论和真实回执。未决的必要项全部标记为 `verification`，且本次所有活跃失败各自在这些未决项中有相同作用域和工具调用 ID 时，裁决者可以结束当前取证并交接。交接提示保留本裁决目标上的检查义务。同一群其他任务的检查继续留在其原任务上。

成员用 `[BLOCKED]` 表达目前拿不到足够证据时，成员报告保留这句话、实际运行状态和签署原件。宿主不发布这次私有工作区，评审队列保留未决状态，并在新委派中让原独立裁决者检验同一冻结输入。这一步可以重新打开真实网页、改用从 DOM 得到的定位器，或按原口径执行其他可用探针，再次逐项签署。重新签署通过仍须满足原条件。签署后的旧浏览器重放记录保存在审计记录中。

冻结快照变化、未交必需文件、尚未执行的验证脚本、仍在运行的命令、独立硬检查未通过、未被签署结果覆盖的失败、取消、截止时间或用户总预算耗尽，都会阻止这条恢复路径。首次办理取证未决允许再次获得证据。同一版本再次提出相同未决证据会停止；即使更换了工具调用 ID、理由或回执，必要未决项集合也须严格缩小才能再次派工。
