## 界面和后端如何取证

这次交付的 `app.py` 在顶层字符串中保存完整 HTML，根路由直接返回原字节。对于本机 HTTP 服务，Studio 在真实浏览器的业务断言处取得主文档正文摘要，匹配到冻结清单中唯一完整 HTML 文件或冻结 Python 源文件中的完整 HTML 字面量。源码扫描采用 Python AST，不导入产品模块。变换后的模板、重复的文档、错误页面和只访问端口均无法提供这种界面归属。直接读取控件就超时时，只有从相应调用传播到脚本出口的真实 Playwright 错误能够记录失败页面。

网页响应可以标识已经实测的界面。后端行为须执行相应业务，再判断结果。举例，独立角色可用 `api = runpy.run_path("实际入口.py")` 加载冻结模块，调用实际的容量、校验或存储方法，对返回值做断言并打印本次检查结果。要验证命令的输出，可以直接运行工作区中的 Python 入口并断言其实际 stdout。只检查退出码无法证明输出正确。需要验证后台服务时，从冻结副本启动原命令、请求端点、验证状态变化并清理进程。宿主不会利用测试自行报告的端口推断后端进程或计算逻辑的身份。

## 上游依据与回归

pytest 的 `TestReport.from_item_and_call` 根据调用的执行阶段和异常类别分别记录失败、通过和跳过。序列化测试逐一比较重建后的跳过、失败状态。本项目使用 RAO 已有的跳过类型，保留原工具诊断及独立于该诊断的业务验证状态。[pytest 判定源码](https://github.com/pytest-dev/pytest/blob/8.4.2/src/_pytest/reports.py#L334-L390) · [报告往返测试](https://github.com/pytest-dev/pytest/blob/8.4.2/testing/test_reports.py#L160-L210)

CPython 的 `runpy.run_path` 从给定路径运行脚本并返回命名空间，标准库测试包含对独立脚本与路径对象的执行。这里沿用标准库的模块入口，实际行为仍由评审者调用并断言。[CPython 实现](https://github.com/python/cpython/blob/v3.13.7/Lib/runpy.py#L262-L309) · [脚本执行测试](https://github.com/python/cpython/blob/v3.13.7/Lib/test/test_runpy.py#L659-L682)

运行 `python -m unittest tests.test_embedded_application_review`。用例经过正常 RAO 工具分派、正式签署和第三方争议队列，也覆盖错误文档、重复文档、未执行的读取和单纯检查退出码。
