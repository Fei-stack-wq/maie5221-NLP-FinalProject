# 原生断言有反证时的群内独立复核

软件第 1 题第 6 轮 `studio-20261119-214117-9707bb2ca201` 的开发者在第 16 步检查四间房的容量。浏览器显示 B202 容量为 8，但检查错误地要求每间房的容量都等于 12。第 17 步按各房间自己的预期值检查，在同一版本成功跑完。第 18、25 步重放原断言，仍然失败。当时还有一项独立的 `python3 tests/test_api.py` 待复验。旧实现将这项待办作为拒绝交接的条件，也会因随后编辑文件或重放原错误而遗失已经观察到的反证。

## 交接与发布条件

1. 对作者本次分工内完整、可归属的 Python 或浏览器失败，保留其最初工具调用、源码、错误、工作区摘要和涉及的产品文件。仅在随后同一版本上用同类工具对同一产品文件取得实际成功断言时，为该原失败登记调查线索。单独打印成功、对无关文件的断言及中断的检查均不足以建立关联。
2. 原断言有时只比较先前读出的本地变量。若浏览器没有签发失败断言直接读取文件的回执，但已签发本次运行中对唯一页面执行过成功断言的回执，宿主单独记录该页面作为调查线索。独立评审必须在待发布的当前页面再次检查实际控件或数据。多个不同页面的先前成功观察不能推断出失败发生在哪个产品上。
3. 交接时冻结**当下**的文件，把每条原失败、历史反证的调用 ID 与版本、其他待执行脚本的范围和当前摘要一起交给独立成员。再执行旧失败或在后来修改代码、数据、说明，都保留历史事实。评审者对当前产品执行新断言，直接复跑独立的原命令，并按原标准签署。触发真实产品缺陷、缺少待办回执、候选哈希不符或使用作者的旧成功回执都会阻止发布。
4. 当作者明确选择 `ask_human.decision_kind=internal_routing` 并已有上述证据，宿主完成冻结交接并安排独立复核。成员仍可向用户确认业务要求、偏好、数据或外部权限。

pytest 的 `LFPlugin` 按实际运行的测试节点更新失败记录，收集失败与用例失败各有独立处理。其回归测试在两个文件中引入导入错误，再仅复跑其中一个，检查另一个文件仍然待处理。Studio 借鉴独立维护每项义务的办法，并将可调查的历史回执与当前候选的发布签署分开记录。[pytest 8.3.4 的结果处理](https://github.com/pytest-dev/pytest/blob/8.3.4/src/_pytest/cacheprovider.py#L324-L339) · [部分复跑与导入异常的回归用例](https://github.com/pytest-dev/pytest/blob/8.3.4/testing/test_cacheprovider.py#L551-L607)
