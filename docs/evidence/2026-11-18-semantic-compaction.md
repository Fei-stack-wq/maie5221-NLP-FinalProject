# DeepSeek 滚动摘要实测

2026-11-18，通过官方 `api.deepseek.com` 的 `deepseek-flash` 对一段合成的预约排障历史进行了两次无工具摘要调用。测试主动触发压缩，保留最近两批工具调用及其结果，主任务保持启用 thinking，摘要调用单独关闭 thinking。

| 调用 | 实际发送的摘要资料 | 服务端报告的输入 token | 服务端报告的输出 token |
| --- | --- | ---: | ---: |
| 第一次 | 6 批旧工具操作的节选 | 1,859 | 207 |
| 第二次 | 上一版摘要和 1 批新增操作的节选 | 634 | 230 |

两次均尝试一次，合计 2,930 token。程序验证两次输出均含目标、决定、文件、检查、阻塞五个字段，均保留工单标记 `CEDAR-47` 及页面 `23:45–24:00` 的失败边界。两次投影的最新工具操作和原始合成历史逐条保持一致。

另一个离线回归从正常 `Agent.run` 入口执行九次文件读取，验证下一次主请求确实包含摘要，并对照 `RunResult`、预算计数和运行报告中的摘要用量。真题交付需另行检查用户获得的文件。[端到端回归](../../tests/test_compaction_runtime.py) · [摘要与故障回退测试](../../tests/test_semantic_compaction.py)
