# 独立评审退回后如何恢复一次到期的作者请求

基金第六题第四轮出现两次真实的作者请求到期。首次返工写出了新的 HTML，第二次从相同 HTML 恢复，修订并运行浏览器检查脚本。成稿摘要和三个遗留失败项相同，脚本已有新的退出码。旧宿主据此把已签过的评审置为 `blocked`，关闭负责人的工具。根任务当时还剩 334.56 秒。未发布的修订和独立风控结论均留在原归档中。

宿主现在按模型适配器返回的 `deadline_exceeded` 识别中断。冻结副本恢复时会再次核对内容与公开基线。团体预算预留原验收者和负责人，再检查原作者及验收者的可分配额度。两者都需要有运行时间、工具和决策额度，以完成返工和重新签署。原作者收到的仍是原评审退回的分工。直到作者交接并取得该版本的新签署，私有候选仍处于未验收状态。成员报告的 `interrupted_repair` 字段记录提供方错误码、恢复的检查点、剩余秒数、双方份额、负责人预留和停止原因。

同一份交付出现重复超时时，允许继续的依据包括原有失败集合严格缩小、对约定文件取得新的可归属断言，以及原先失败的同一检查脚本首次真实退出成功。脚本退出能证明这次运行完成，独立验收者仍须判断其是否证明业务要求。换调用 ID、增加无关失败、重复读文件或改写交接说明都不会使监测到停滞的工作重新派发。用户取消、完整性检查失败、不可恢复的模型错误与实际预算不足各自保留原因并停止。

OpenAI Agents SDK 的 `network_error` 策略读取结构化异常。其模型重试测试分别验证了超时、取消和缺少安全重放依据的处理。这里沿用异常分流与恢复前验证两点。Studio 按已冻结的成员工作区恢复原作者，结合剩余团队预算、已取得的真实证据和独立签署决定下一步。未复制上游代码。 [OpenAI Agents SDK 固定版本源码](https://github.com/openai/openai-agents-python/blob/6115461c6b0f661398d63b1de2b3ecc9390a5a09/src/agents/retry.py#L338) · [超时重试测试](https://github.com/openai/openai-agents-python/blob/6115461c6b0f661398d63b1de2b3ecc9390a5a09/tests/models/test_model_retry.py#L1918) · [取消优先测试](https://github.com/openai/openai-agents-python/blob/6115461c6b0f661398d63b1de2b3ecc9390a5a09/tests/models/test_model_retry.py#L2686)

[正常群聊入口回归](../../tests/test_interrupted_review_repair.py)模拟剩余 334.56 秒，保留 90 秒收尾和 15 秒分派后，作者可再获约 114.78 秒。该测试恢复字节相同的冻结副本、执行新检查，再让原风控重新签署。反例覆盖只有读取和无关检查、预算仅剩 95 秒、提供方拒绝和用户取消。私有原候选另有独立用例检查发布与签署顺序。第四轮两份真实只读检查点也已离线回放，均获准继续；对第二份不做更改重放一次则停止。公开演示的原始盲测与事实问题保持如实归档。
