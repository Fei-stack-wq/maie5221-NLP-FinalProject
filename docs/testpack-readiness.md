## 使用入口

从仓库根目录运行。离线配置检查可在 Windows 使用；Studio、原生进程清理及完整试跑使用 Linux/macOS。

```sh
python -m miniagent.testpack check
python -m scripts.run_testpack_smoke --output runs/smoke-1
python -m unittest discover -s tests -t . -v
```

`smoke-1` 必须不存在，避免覆盖证据。离线试跑将三组六题替换为明确标注的协作夹具：负责人向模拟答复器提问，第一名成员运行 Python 生成数据，第二名成员以另一公式核验，第三名成员读取结果、请求删除临时文件审批并交付说明；Task 2 读取 Task 1 数据。脚本使用 `ScriptedProvider`，问答和批准均为模拟输入，**不是真人试验或真实模型成绩**。

真实模型运行使用当前进程的环境变量；命令不会自动寻找或加载 `.env`：

```sh
# 先在宿主配置有效的 DEEPSEEK_API_KEY 及课程确认的受支持模型。
python -m miniagent.testpack run --scenario news --runs-dir runs/testpack
# 不指定 --scenario 时依次运行三组；每组首题失败会阻止该组第二题。
```

必要澄清显示在终端；审批必须明确回答“批准”或“拒绝”。没有有效答复会停止依赖动作并留存失败记录。整组预算含等待时间；CLI 的 `--yes` 只记录为自动批准策略，不能生成虚构的业务需求答复。不同实验使用新输出目录及新团队。

Studio/API 的新群组可设置 `conversation.memory_enabled=true`。后续轮次默认继承开关；关闭时不检索或记录经验，`inherit_files=false` 会从空经验副本开始。经验保存在运行目录的 `role-memory.json`，不进入成员项目副本；每个角色最多保留八条已发布回执，检索最近三条。原回执和验收记录仍是证据，经验摘要不能当作新一轮验收。

Git 发布默认关闭。宿主明确配置 `MA_GIT_TEST_REMOTE` 后，Studio 成员才获得 `git_publish`。只允许指定的 GitHub HTTPS 仓库或本地裸测试仓库，模型不能替换远端；仅创建 `nlp-test/<name>` 新分支。先保存文件快照并准备提交，再展示远端、分支、提交和逐文件哈希请求批准，最后回读远端提交验证。已有分支或并发创建会被拒绝，不修改主分支。工具执行时限同样适用；批准过晚导致时限不足时不发布。普通 shell 仍是本机软隔离能力，这不是对任意恶意代码的安全沙箱声明。
